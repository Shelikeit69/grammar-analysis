## 2026-11-01

- **任务 B 的待定项全部确认，分两个 PR 实施。**
  做法与理由：
  - 长从句拆分条件：超过 6 个英文单词，或内部包含嵌套从句时，要求模型拆出内部主语、谓语及其他必要成分；短从句可以保留为一个片段。只含介词短语不是强制拆分条件，不为增加框数量逐词拆分。词数口径沿用应用现有英文词数规则（缩写和连字符一致）。
  - 仅「显示详细结构」开启时画出从范围条带；默认主干视图保持简洁。英文下方细线 + 编号，对应下方编号从句清单，第一版不加点击、折叠或悬停交互。同句现有成分标签、引线和条带要留出空间，不互相覆盖。
  - 第一版支持定语从句（relative）、宾语从句（object）、状语从句（adverbial）；状语从句可带 time、condition、reason、concession、purpose、result、comparison、manner 小类，不确定时只写「状语从句」。最多三层嵌套。单片段短从句不画条带，但仍在清单里显示。
  - 多个时态：主句优先，然后按从句在原文中的顺序；相同组合只写一次。这是模型输出要求，不在本地靠字符串重排猜测主句，`tenseReason` 也要能区分主句和从句。
  - 数据结构：保留平铺 `segments` 与原文逐字覆盖，新增可选句级 `clauses`（`start` 含、`end` 不含，空格标点计数）；不让模型输出 id、depth、编号、重复原文或 parent。交叉的两项都丢，最外层为第 1 层，超过 3 层的内层项丢弃；候选超过 200 项时忽略整句 clauses。任何 clauses 错误只影响该可选信息，不抛 `AnalysisValidationError`，不触发付费修正。
  - **PR 1（`feat/clause-data`）**：clauses 校验/归一化、SYSTEM 规则、时态规则、反馈从句清单、文档与测试。不写长从句强制拆分提示词，不画条带，不写 `Fixes #27`。
  - **PR 2（`feat/clause-brackets`）**：长从句拆分提示词、`level` 规则（主句主干 core，从句内部拆分成分 detail）、详细视图条带、多层轨道、跨行绘制与重排清理。PR 1 经独立审核并合并后，才从最新 main 新建分支，PR 写 `Fixes #27`；真实模型和上线实测仍由负责人完成。
  验收原则不变：写代码的工具不验收自己的 PR；PR 1 的自动检查不等于真实验收。

## 2026-11-01（PR 2 实现）

- **PR 2「长从句拆分与从句条带渲染」按 2026-11-01 确认的方案实现，待独立审核与上线实测。**
  做法：
  - 从 PR 1 合并后的最新 main（`27ea37c`）新建 `feat/clause-brackets`。SYSTEM 重写长从句段落：超过 6 个英文单词或含嵌套从句时拆出内部主谓；6 词及以下的短从句可整框；仅介词短语不强制拆、不逐词拆。旧的「一成分一框」措辞限定为「Outside the long-clause rule below, one constituent is one span」，旧示例的 5 词短从句保留整框，不再与长从句规则冲突。
  - 主句主干和并列主句用 `core`，从句内部拆分成分用 `detail`；默认视图只显示 core。长从句拆开后 `clauses` 范围仍覆盖全部片段，嵌套时内外层都给出。
  - 详细视图在英文下方画范围条带，按实际文字矩形分行；深度 1/2/3 用不同轨道（13px 间隔），有底标签时预留 58px。编号与「从句清单」一致；单片段短从句只列清单、不画线。条带层 `aria-hidden`、`pointer-events:none`、无 tabindex。
  - 布局在 ResizeObserver、窗口 resize、字体加载、大字切换后重排；重分析、换例句、清空时移除旧条带和清单。大字 CSS zoom 的坐标按「实际宽度 / 本地宽度」换算回本地 CSS 像素。
  - `predicateOf` 边界保持不变：两端 predicate/core，只服务主句里被宾语隔开的短语动词；SYSTEM 明确从句内部的 `detail` 不输出不适用的 predicateOf，校验不放宽。测试同时覆盖「从句 detail 的 predicateOf 被丢弃」和「主句分离谓语保留」。
  - 内置例句补 `clauses`；`who keep going every day` 是 5 词短从句，保持单片段，只显示清单、不画条带，不为展示条带改写原句。嵌套、跨行演示只用测试夹具和审核截图。
  - `TOOL_VERSION` 改为 `2026-11-01.2`（预定合并日 + 序号）。
  原因：Provider 层拆分依赖模型输出，客户端不猜语法；条带无交互可以先把「范围」讲清楚，再评估点击交互。已知限制写入 README、架构文档和验证记录，不提前声明真实模型已稳定修复 #27。

## 2026-11-02

- **长宾语从句保留自己的主干为 core。**
  原因：样例 09 `I know that she was working when you called.` 在 PR #34 的统一 detail 规则下，默认视图主干只剩 I know，丢掉了宾语。
  做法：仅主句的长宾语从句拆开时，其自身主语中心词、谓语或系动词、宾语或表语保留 core；引导词、修饰语及嵌套从句均为 detail。定语从句、状语从句拆开后仍全部 detail，宾语从句内嵌的定语或状语从句也不例外。6 词以内、无嵌套且保持整框的宾语从句仍是 object/core。拆开的从句内部不输出 predicateOf，即使宾语从句谓语为 core；主句分离谓语和 predicateOf 校验不变。默认视图应显示 I know … she was working；详细视图仍显示全部成分、从句条带和清单。仅改 SYSTEM，不让客户端按从句类型改写 level。当前 TOOL_VERSION 为 `2026-11-02.1`。
  相关：#27、#34。旧条目保留为历史记录；真实密钥验收由负责人完成。
