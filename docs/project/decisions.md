# 决策记录

按时间顺序记录。格式：日期 · 决定 · 原因 · 相关 PR。新决定往下追加。

## 2026-10-16

- **网页版用「用户自带密钥」，不做后端代理。**
  原因：免费开源，丰俭由人；不用自己承担调用费用，也没有被刷额度的风险。代价是用户要自己注册 DeepSeek 并充值，门槛较高。
  PR #3

- **不把密钥放进 Actions Secrets 再注入网页。**
  原因：静态网页的所有内容对访问者可见，等于公开密钥。

- **仓库改为 Public，开启 GitHub Pages（Source 选 GitHub Actions）。**
  原因：免费账户的 Pages 只能用于公开仓库；仓库历史里检查过，没有密钥。

- **谓语合并成一个框；修复换行后的大段空白。**
  原因：实测时 `for` 被标成谓语，`can`、`shop`、`for` 被拆成三个谓语框；之前每一行都固定预留了标签空间。
  PR #4（2026-10-27 起有例外：被宾语隔开的短语动词拆成两个红框，见 PR #20）

- **加时态黄框和判断依据。**
  原因：时态是学习者的难点；判断依据必须引用原句里的词，防止 AI 编理由。
  PR #6

- **README 重写，面向零基础用户；开发者内容放到后面。**
  PR #5、#8、#12

- **界面采用设计方案 A（课本批注），并加入方案 B 的两点：三步引导、大字开关，图例改成白话说明。**
  原因：改动最小，零基础用户受益最大。方案 C（分栏精读）留到长难句的数据结构确定之后再做。
  PR #7

- **提示词第二轮：缩写否定并入谓语、同一成分不拆框、修饰语不漏标、并列分句和从句的时态分别列出。**
  PR #9、#10、#11

- **换内置例句为 "Tired learners who keep going every day will see the beauty of English grammar in the end."**
  原因：内容本身激励学语法的人；详细视图里颜色丰富，适合截图展示。
  PR #13

- **main 开启分支保护 protect-main。**
  规则：禁止删除、禁止强制推送、必须走 PR（审批人数 0）、必须通过 `test`；Repository admin 可以绕过。

- **不加统计代码。**
  原因：保护隐私。代价是拿不到使用量数据，证明有人用只能靠反馈记录。

- **推广：先在 r/languagelearning 当月的资源分享置顶帖发一次评论。**
  原因：版规只允许在这里推广，同一作品 6 个月内不能重复发，也不能在其他帖子里提。中文社区（V2EX「分享创造」、小红书）备选。

- **可视化下一步拆成两单：A 修饰高亮（`modifies`），B 从句条带（`clauses`），先 A 后 B。新增的可选字段不合规时只丢字段，不拒绝整个结果。**
  原因：两个功能都要改提示词、校验、渲染和测试，合在一起风险太大；AI 偶尔数错下标，不该因此让整句显示不出来。

## 2026-10-19

- **合并 PR #15（可靠性修复），再合并 rebase 后的 PR #14。**
  原因：两个 PR 都改了校验和提示词，无论哪个先合，另一个都会冲突；先合大的（#15），再把小的（#14）重新套上去更稳。

- **修复密钥留空保存会清掉已存密钥的 bug。**
  原因：用户只改模型名称再保存，就会丢失密钥。现在留空表示保留，只有点「清除」才删除。
  PR #15

- **校验失败时自动让模型修正一次。**
  原因：AI 偶尔返回格式不对的结果，以前用户只能整次重来。只针对 JSON 语法和核心字段错误；网络、超时、取消等错误不重试。修正结果照样完整校验；会多花一次用户额度，界面事先提示。
  PR #15

- **时态和判断依据字段不合规时改为只丢字段，不再拒绝整个结果。**
  原因：和 `modifies` 的处理方式保持一致；时态只是补充说明，不该连累整句的显示。核心校验没有放宽。
  PR #15

- **CI 和自动部署加入浏览器测试。**
  原因：排版问题单元测试测不出来。代价是每次运行时间变长，浏览器测试偶尔不稳定可能卡住部署；如果频繁出问题，再考虑把它从部署流程里拿掉。
  PR #15

- **点击定语、状语、补语时，高亮它修饰的词（`modifies`）。**
  PR #14

- **Structured Outputs 暂不迁移。**
  原因：现在用的是 JSON 模式。DeepSeek 的严格 Schema 只在 Beta 版工具调用里提供，迁移要改请求和解析方式，收益还不确定，以后单独评估；即使接入，也保留逐字覆盖原文的校验。

  原因：原来是 12px 绿色小字，和说明文字差不多，看不出来能点。
  PR #22

- **分工：代码 PR 由 Codex 开，Claude 负责写任务单、验收 PR、同步知识库。**
  前提：仓库加入 AGENTS.md，禁止 superpowers / 子代理流程和提交计划文件（PR #23 已加）。

  原因：手动关容易忘，Issue 会一直挂着；合并前由 AI 验收 PR。
  补救：上线后的真实复测仍然要做（workflow.md 第 7 步）；复测发现没修好，就重新打开（Reopen）原 Issue，或开一个新 Issue 引用旧编号。
  仓库文档已在 PR #24 改回；AGENTS.md 也写明了。#19 是在这条决定之前用 `Refs` 合并的，复测后已手动关闭。

- **反馈窗口改成普通人能看懂的简单表单。**
  做法：只读原句 → 问题类型（可多选）→「具体说说」→「正确的应该是？」（选填）→ 折叠的「查看会发送的完整内容」→ 公开提示 +「我知道内容会公开」→「去 GitHub 提交 →」，下面一行写明还要在 GitHub 点 Create。标题自动生成；正文从 JSON 改成易读 Markdown，GitHub 上直接能看懂，也让单句链接回到 6000 字符以内（内置例句约 5200）。
  原因：旧窗口直接显示整段 JSON，普通用户不会拉到最下面写原因；按钮「打开 GitHub 预填页面」看不出会发生什么；JSON 让链接约 8000 字符，几乎每次都要手动粘贴。
  保留：预览（折叠，不删，隐私要求）、公开确认、不带密钥/设置/请求头。
  PR #25

- **不做「自动提交 Issue」，继续用 GitHub 预填 + 用户点 Create。**
  原因：真正自动提交需要后端和 GitHub token，跟 10-16「不做后端、不存东西」冲突，还要防刷。代价是用户必须有 GitHub 账号。等真的有人因为没账号放弃反馈，再重新评估。

## 2026-10-29

- **项目资料搬进仓库 `docs/project/`，作为唯一来源；所有编码工具共用 `AGENTS.md`。**
  做法：原来放在 claude.ai 项目里的概况、架构、提示词规则、决策记录、协作流程搬进 `docs/project/`；个人事项（推广、作品集、简历）不放进公开仓库。`AGENTS.md` 扩充为共用规则；Trae 用 `.trae/rules/project_rules.md`（始终生效）指向它。
