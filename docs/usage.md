# 使用说明（详细版）

README 里只写了最常用的内容，这里是完整说明。

## 第一次使用

什么都不填也能先看效果：打开网页，点「试试一个例句」。

要分析自己的句子，得有一把 DeepSeek 的「密钥」。工具本身免费，但分析是 DeepSeek 的 AI 做的，它按用量收费，所以每人用自己的账户，价格看 [DeepSeek 官网](https://platform.deepseek.com/)。输入框上方有三步提示，做完一步打一个勾。

### 1. 拿到 DeepSeek 密钥

1. 打开 https://platform.deepseek.com/ ，注册并登录。
2. 先给账户充一点钱。余额为零时无法分析。
3. 找到「API Keys」页面，点创建，给它起个名字，比如「句间」。
4. 复制生成的那串字符，它以 `sk-` 开头。这串字符一般只显示一次，建议先存到备忘录里。

### 2. 填进网页

1. 回到 [句间网页](https://shelikeit69.github.io/grammar-analysis/)，点开「设置 DeepSeek 密钥」。
2. 把 `sk-` 开头的密钥粘贴进「API 密钥」一栏。「模型名称」可以先空着。
3. 如果是你自己的电脑或手机，可以勾上「在这台设备上记住密钥」，下次就不用再填。在网吧、学校机房这类公用电脑上不要勾。
4. 点「保存」。

以后只改模型名称时，密钥一栏留空即可保留已有密钥；删除请点「清除密钥」。如果浏览器不允许保存或删除记录，页面会明确提示，当前页面中的设置仍可使用。

### 3. 开始分析

把英文粘贴进上方的输入框。粘贴后不会自动开始，点「分析句子」才会发送请求。一次最多 300 个单词，适合一句话或一小段。

如果 AI 返回的格式不合规，工具会自动要求它修正一次，并显示「正在修正格式，再试一次」。这可能额外产生一次 DeepSeek 调用费用；仍不合规就报错。首次格式合规但长从句没拆开时，也会额外调用一次；重做失败就显示首次结果。两种情况共用一次重做机会。清空或修改原文会取消正在进行的分析，但已经发送的请求可能已计费。

## 怎么看结果

颜色对应的成分：

| 颜色 | 成分 | 例子 |
|---|---|---|
| 蓝 | 主语（谁） | Tired **learners** … |
| 橙 | 谓语 / 系动词（做什么、是什么状态） | … **will see** the beauty … |
| 绿 | 宾语 / 表语（做的对象、状态的内容） | … will see **the beauty** … |
| 紫 | 状语（什么时候、在哪里、怎么样） | … **in the end**. |
| 灰 | 定语（修饰名词的部分） | **Tired** learners **who keep going every day** … |
| 青 | 补语 | |
| 淡黄 | 时态和语态，在句子上方的黄框里 | 一般将来时 · 主动语态 |

结果区的英文用浅底色高亮，标签是上下排列的小色块，点击后有清晰描边。页面使用浅色方格纸背景和白色句子卡片。

标签按成分角色定位：主语、谓语、系动词、宾语、表语在上方，定语、状语、补语在下方；从句内部也按角色定位。从句编号使用灰色方框数字。

几个小提示：

- 刚出来的结果只高亮句子的主干。如果这句有从句，主干下方会显示一行提示，告诉你有几个从句，并引导你勾选右上角的「显示详细结构」查看从句范围和清单。想看定语、状语这些修饰部分以及从句内部，勾选右上角的「显示详细结构」。没有这行提示不代表句子里没有从句：AI 偶尔会漏给从句信息。
- 勾选「显示详细结构」后，一句里最外层的从句都不超过 12 个英文单词时，用外框圈出从句，框套框表示嵌套。有任何一个最外层从句超过 12 个词，就在句子下方画横线标出范围；原文跨行时，横线按行分别画。两种情况下面都有从句清单。只占一个片段的从句不画框也不画线，只在清单里列出。12 是初始值，以后可能调整。超过 6 个英文单词或内部还有从句的长从句，模型仍须拆出内部成分。
- 点任意一个有底色的成分，下方会出现更详细的解释。点定语、状语这类修饰成分时，它修饰的那个词会同时加粗高亮，说明里多一句「修饰：……」；再点一次或点别的成分就取消。AI 拿不准修饰对象时会不标，这时只显示说明、没有高亮。
- 定语和状语下方的标签有时会多写结构类型，比如「定语 · 介词短语（后置）：向原始亚人类状态的」。类型有介词短语、不定式、现在分词、过去分词和从句五种。标了「（后置）」说明这个修饰语放在被修饰词的后面。AI 可能判错类型；修饰关系偶尔指错时，（后置）也可能显示错。
- 成分上方或下方的标签写的是这个词的原形。比如原句是 `felt`，标签会写「系动词：feel－感到」，方便你查词典。`can shop for` 这样连在一起的几个词会合成一个谓语高亮片段。如果短语动词中间插了宾语，比如 `give it up`，会按原文顺序分成 give 和 up 两个橙色高亮片段，点哪段都会解释 give up。
- 黄框里的「判断依据」会写明是看哪个动词形式、哪个时间词判断出的时态。一句话里有并列分句或时态不同的从句时，黄框先写主句，再按从句在原文里的顺序用「；」列出，相同的时态和语态只写一次。
- 一段话里有好几句时，最下面可以展开「查看整段翻译」。
- 字太小就点右上角的「大字」，整页放大，再点一次恢复。这台设备会记住你的选择。
- 如果句子里有语法、拼写、标点或明显搭配错误，错的地方会标红色波浪线 + 红圆字母，字母对应下方纠错列表，句子下方多出一行「纠错：」：先显示整句改后的样子（错的原文带红色删除线，用一个空格隔开的蓝色改法），再逐条列出原文、改法和原因。没有错就不显示。纠错只改这几类错误，不润色、不换说法；语法分析仍按你输入的原文进行。
- 觉得哪里标错了，点这句下面的「这句分析有问题？」。勾一下问题类型，愿意的话写一两句，再点「去 GitHub 提交 →」。GitHub 会在新页面打开，内容已经填好，你点 Create 就提交了。不知道正确答案也没关系。需要 GitHub 账号，提交后会公开。

## 纠错实测数据

我用几组固定的测试句，对当前版本（TOOL_VERSION 2026-11-09.1）做了重复测试，每组测 10 到 15 次，每次单独调用 DeepSeek，共 120 次。一句里有几处错，就按错误类型分别统计。

![纠错实测：当前版本按错误类型统计的改对次数](images/correction-reliability.svg)

主谓一致、祈使句用原形、动词搭配、名词单复数这几类基本都能改对，本来没错的地方也很少被乱改。时态是最弱的一类：本句有 Yesterday、Last summer 这类时间词时，40 次改对 26 次；同一句里有两个谓语时，25 次没有一次改成前后一致，比如把 wake 改成 wakes，后面的 took 却没动。另外，把整篇作文贴进去时，被纠正的词原形可能标成改后的词：made 有 10 次，只有 3 次标成 make。

所以纠错适合用来找主谓一致、搭配这类问题；动词时态怎么改，请结合上下文自己判断。

每类只有 1 到 3 个测试，图上的数字只说明这几句的结果，不代表这一类语法整体的正确率。模型每次的输出也有波动，只能看大致趋势。

句子分析也有类似的倾向：长句和多层从句更容易出错，短句相对可靠。这一点没有做同样的重复统计。

逐次记录见 [docs/verification.md](verification.md)。

## 常见问题

**密钥安全吗？**
密钥只从你的浏览器发给 DeepSeek，不经过别的地方。不勾「记住」，关掉网页就没了。详细说明和自己核实的方法见下面的「密钥与隐私」。

**AI 会分析错吗？**
会，尤其是很长、很绕的句子，成分和时态都可能标错。把它当成帮你理解的工具，拿不准的地方对照课本或问老师。纠错按错误类型的实测数字见上面的「纠错实测数据」。

**提示「DeepSeek 拒绝了这个密钥」**
密钥可能没复制完整，或者前后多了空格。重新复制一遍再保存。

**提示「账户余额不足」**
去 DeepSeek 官网充值。

**提示「请检查模型名称」**
在「模型名称」一栏填 DeepSeek 官网上写的、你账户能用的模型名，然后保存。

**提示「浏览器无法直接连接 DeepSeek」**
先检查网络。如果网络正常仍然出现，可以在 GitHub 上提一个 Issue 告诉我。

**这个工具会保存我输入的句子吗？**
平常分析时不会，英文只发给 DeepSeek。反馈是例外：你点「去 GitHub 提交 →」，原句、这句的分析结果和你写的说明会带到 GitHub；你在那边点了 Create，它就成了公开的 Issue，会一直留着。所以原句里有个人信息的话，先别提交反馈。

## 密钥与隐私：这个网页会拿你的密钥做什么

这是我的个人试验项目，不收费，页面里没有广告和统计代码。你填的 DeepSeek 密钥会经历这些：

- 密钥只会作为请求头发给 `api.deepseek.com`，用来替你调用 DeepSeek。网页版没有自己的服务器，没有别的地方会收到它。
- 页面带有内容安全策略（CSP），浏览器只允许它连接本站和 `api.deepseek.com`，不能把数据发到其他域名。可以在 `public/index.html` 里看到这一行。
- 页面只加载自己的 `app.js` 和 `styles.css`，没有第三方脚本、字体或图片。
- 默认只在当前页面里保存密钥，关掉网页就没了。勾选「在这台设备上记住密钥」后才会存进你自己浏览器的 localStorage。点「清除密钥」会尝试删除；如果浏览器阻止删除，页面会提示你手动清除本站数据。
- 你输入的英文会发给 DeepSeek，按它的规则处理。这部分我管不了，介意的话先看看它的隐私政策。
- 费用从你的 DeepSeek 账户扣。每次分析输入不超过 300 词，每次模型调用输出最多 16000 个 token；格式修正最多额外调用一次，并会附上第一次的错误输出供模型纠正。

以上只适用于官方地址 https://shelikeit69.github.io/grammar-analysis/ 。别人 fork 或搬走的副本我没法担保，请不要往来路不明的网页里填密钥。

不想光听我说，可以自己查：

1. 打开浏览器开发者工具的「网络」页，点一次分析，看请求是不是只发到了 `api.deepseek.com`。
2. 代码全部公开，搜 `apiKey` 就能看到它被用在哪里。
3. 在 DeepSeek 开放平台单独建一个密钥，账户里只留少量余额，试完就删。用任何网页工具都可以这么做。

## 分析问题反馈

每句结果及请求失败提示旁都有反馈入口。表单先显示只读原句，再选择问题类型、填写「具体说说」及可选的正确答案；请求失败不显示类型选项，需填写说明。至少选择一个问题类型或填写说明，再勾选「我知道内容会公开」，才能点「去 GitHub 提交 →」。如原句有个人信息，请取消反馈，修改输入后重新分析。

标题和易读的分析正文会自动生成，展开「查看会发送的完整内容」可查看只读预览，其中包括单句分析（有从句时还包括从句名称、可选小类和对应原文；有纠错时还包括纠错原文、改法和原因）、请求时实际模型和工具版本；失败反馈只含安全提示。打开链接会把预览内容带到 GitHub，新标签页已填好内容，仍需你在那里点 Create 完成提交，需要 GitHub 账号。提交后会公开，请不要填写姓名、联系方式等个人信息。不会自动提交 Issue，也不会附带设置、密钥、请求头或原始提供方响应。手机端操作区固定在弹窗底部。

预填链接超过 6000 字符时不会截断正文：保留真实标题，并按「① 复制反馈内容」「② 打开 GitHub 粘贴 →」两步操作，再点 Create。第 2 步在复制前禁用；修改内容会重置复制状态和公开确认。自动复制失败会全选正文供手动复制，手动复制好之后再点第 2 步。剪贴板可能保留内容，需要时请自行清除。反馈草稿不保存到浏览器存储，关闭预览或更换输入会清除草稿。

## 试验与合作

项目刚起步，AI 时不时会判错，我也还在摸索怎么让它稳一点。想帮忙的话，下面这些最有用：

- 提交判错的句子：最方便的是点结果下面的「这句分析有问题？」，原句和分析结果会自动带上。也可以直接在 GitHub 开 Issue，贴上原句、你看到的结果和哪里不对。正确答案可以不写。
- 测试不同的句型、时态和模型，告诉我哪里不稳定。
- 改提示词、改排版、补测试，直接提 PR。
- 教英语或学英语的人提意见：哪些标注对初学者有用，哪些看不懂。
