# 给开发者

本地运行、部署、代码结构、测试和校验规则。只用网页版的话不需要读。

下面的内容是给想自己运行、修改代码的人看的。只是使用网页版的话不需要读。

## 三种运行方式

| 方式 | 密钥放在哪里 | 适合 |
|---|---|---|
| 网页版（GitHub Pages） | 访问者自己的浏览器 | 普通使用，每人用自己的密钥 |
| Codespaces | Codespaces Secrets | 不装软件，在 GitHub 云端私有测试 |
| 本地运行 | 本机 `.env` | 开发、修改代码 |

三种方式共用 `public/` 里的同一套页面。页面会先请求 `./api/status`：有后端回应就用后端保管的密钥（本地和 Codespaces），没有回应就显示密钥面板，由浏览器直连 DeepSeek（Pages）。

## 网页版的部署

`.github/workflows/pages.yml` 会在每次推送到 `main` 时先跑测试，再只发布 `public/` 目录，不使用任何 Secrets。

第一次开启需要两步：仓库 Settings → General 改为 Public（免费账户的 Pages 要求公开仓库，仓库里没有密钥），然后 Settings → Pages → Source 选 GitHub Actions。

页面通过 meta 标签设置了内容安全策略，只允许连接本站和 `api.deepseek.com`。不要把密钥放进 Actions Secrets 再注入网页：静态网页里的任何内容访问者都能看到，等于公开了密钥。

## Codespaces

把密钥存为 Codespaces Secret（名字 `DEEPSEEK_API_KEY`，放在 Codespaces 而不是 Actions 下），从 `main` 创建 Codespace，在终端运行 `npm start`，在「端口」面板打开 3000。端口保持 Private。详细步骤见 [GitHub 测试指南](github-testing.md)。

## 本地运行

需要 Node.js 22.9 或更新版本，没有第三方运行时依赖。

```sh
git clone https://github.com/Shelikeit69/grammar-analysis.git
cd grammar-analysis
cp .env.example .env        # Windows PowerShell：Copy-Item .env.example .env
```

用文本编辑器在 `.env` 里填写 `DEEPSEEK_API_KEY`，然后：

```sh
npm start
```

打开终端显示的地址（默认 `http://127.0.0.1:3000`），按 Ctrl+C 停止。修改 `.env` 后需要重启服务。

本地常见问题：提示没有配置密钥时，确认文件名是 `.env` 而不是 `.env.txt`，并且放在仓库根目录；端口被占用时，在 `.env` 里改 `PORT`。

## DeepSeek 配置

默认模型为 `deepseek-flash`，本地可用 `DEEPSEEK_MODEL` 修改，网页版在页面上的「模型名称」修改。接入依据：[官方 API 文档](https://api-docs.deepseek.com/)和 [JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)。

真实分析会把输入的英文发给 DeepSeek，并按密钥所属账户计费；内置例句不会发送请求。应用不保存正常分析的输入或历史；主动提交到 GitHub 的公开反馈会持久保存。

## 校验与限制

- AI 返回的结果会先经过 `validateAnalysis` 校验：每句的片段必须和原文逐字对上。模型内容不是有效 JSON、缺少核心字段或与原文对不上时，最多自动修正一次；第二次仍执行完整校验，失败则拒绝显示。首次校验通过后还会检查单片段长从句，与格式修正共用一次重做机会，失败回退首次合规结果。这只能检查格式和原文对应，不能保证语法判断正确。
- 不合规的可选 `tense` / `tenseReason` 会被丢弃，不触发额外调用。网络错误、HTTP 错误、超时、取消、超长或截断响应、服务商响应外层解析失败均不会触发格式修正。
- 两次调用共用一个截止时间：网页版总计 90 秒，本地 / Codespaces 默认总计 45 秒；不会因修正而重新计时。
- 修饰关系（片段的可选字段 `modifies`，指向它所修饰的片段下标）不合规时（越界、指向自己、指向标点空白、不是整数）只会丢掉这一条，整句分析照常显示，所以不会因此拒绝整个结果。合规不代表对：AI 可能把修饰对象标错，高亮只作参考，请对照原句判断。
- 相邻的情态动词、助动词和短语动词仍合为一个谓语框。被宾语隔开的短语动词保留原文顺序，显示两个橙框，例如 should give / it / up；it 独立为宾语。点击任一橙色高亮片段都解释 give up（放弃），should 的情态含义写在说明中；两个橙框不联动高亮。提示词只能降低出错概率。
- 分离粒子的可选字段 `predicateOf` 指向同句较早的主谓语片段下标（从 0 开始，空格和标点也计数）。两端必须均为 predicate/core、原形完全一致，目标不能再带 predicateOf，两端之间须有实质成分；相邻粒子仍合框。不合法时只丢弃该字段，不触发付费修正。旧结果无此字段也可显示。
- 时态和判断依据也是 AI 给的，可能判断错或引用错，同样没有自动校验。多个时态按「主句优先，再按从句在原文中的顺序，相同组合只写一次」的要求输出，但模型不一定遵守。
- 片段数据仍然是平铺的；从句内部成分按模型结果显示，详细视图通过嵌套外框或范围横线及下方清单说明从句关系。AI 会额外返回可选从句范围（`clauses`）；详细视图根据最外层从句的词数选择嵌套框或范围横线，并显示从句清单，反馈正文也会列出从句名称和原文。默认视图只保留主句主干（`core`），从句内部拆分出的成分通常用 `detail`，只在详细视图显示。仅主句的长宾语从句拆开时，其自身主语中心词、谓语或系动词、宾语或表语保留 core；引导词、修饰语及嵌套从句均为 detail。定语从句、状语从句拆开后仍全部 detail，宾语从句内嵌的定语或状语从句也不例外。6 词以内、无嵌套且保持整框的宾语从句仍是 object/core。拆开的从句内部不输出 predicateOf，即使宾语从句谓语为 core；主句分离谓语和 predicateOf 校验不变。长从句拆分只在提示词层要求，真实模型不一定每次都拆开或拆对，从句类型也可能给错（Issue #27）。从句范围已改用原文锚点由代码匹配，范围是否完整仍以上线实测为准。只有直接充当主句谓语宾语的宾语从句才保留自身 core 主干；被定语从句、状语从句或另一个从句包住的宾语从句不适用。反例 `She thanked the nurse who said that the results were good.` 中 the results、were、good 全部 detail，默认只显示 She thanked the nurse。
- 从句范围由 AI 照抄从句原文，去掉首尾空白后，在片段边界上精确匹配；不能唯一匹配（无匹配、多处匹配、边界落在片段中间）、原文过长或类型不对时丢弃该项，不信任模型提供的下标。匹配后收掉首尾纯空白或标点片段；同范围去重，部分交叉两项都丢，最多三层。不是数组或候选超过 200 项时忽略整句从句信息。整句照常显示，不触发付费修正。合规只说明格式对得上，不代表 AI 分对了从句。
- 横线模式的范围线只覆盖含字母或数字的片段；只有一个这样片段的短从句保留清单编号，不画框或线。框头、条带和编号是装饰，不进入 Tab 顺序、不拦截成分框的点击，完整信息以可访问的从句清单为准。
- 已知限制：拆开的从句内部不会输出 `predicateOf`，包括保留为 core 的宾语从句谓语；`predicateOf` 仍然只用于主句里被宾语隔开的短语动词，原有校验未放宽。长从句拆分、嵌套范围是否正确，本轮只做了提示词与模拟数据检查，不能代表真实模型已经稳定。
- 定语和状语的结构类型（`form`）是 AI 给的，可能判错；`modifies` 偶尔错位时，代码根据 modifies 下标判断的「（后置）」标记也可能显示错。form 不合规时只丢字段，不影响其他分析。
- `must have been working` 这类情态完成结构的时态名称可能被简化；模型输出有随机波动，同一句多次分析的框和措辞可能略有不同。
- 输入最多 300 个英文单词、6000 个字符。
- 纠错只指出错误并给出改法，不会改写原句；纠错由 AI 给出，可能漏判，也可能把正确的写法改错。
- 本地和 Codespaces 的服务只监听 `127.0.0.1`，没有账号系统。不要通过公网隧道或反向代理直接暴露它。

## 代码结构

- `public/`：页面、样式、批注排版、内置例句，以及和后端共用的 `analysis.js`（校验）和 `deepseek.js`（DeepSeek 请求与提示词）。
- `lib/`：转发 `public/` 里的共用模块，供 Node 使用。
- `server.mjs`：本地和 Codespaces 用的 HTTP 服务与访问边界。
- `tests/`：原文对应、接口错误、安全边界和提示词规则测试。
- `docs/`：测试指南、验证记录和设计文档；`docs/project/` 是项目资料（概况、架构、提示词规则、决策记录、协作流程）。
- `AGENTS.md`：所有编码工具共用的规则；`.trae/rules/` 和 `CLAUDE.md` 分别给 Trae 和 Claude Code。

## 测试

```sh
npm test
```

测试使用模拟的 DeepSeek 响应，不消耗额度。GitHub Actions 在每次 push 和 PR 时运行。

浏览器检查（CI 与 Pages 发布前也会执行）：

```sh
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
npm run test:browser
```

它同样使用模拟响应，覆盖原文保留、色块标签位置、手机宽度布局、换行间距、详情切换、修饰对象高亮（点击、再点取消、回车键、390px 无横向滚动）、粘贴后不自动请求、清空和多句翻译；也覆盖纠错波浪线位置、默认与详细视图的纠错行、标点和普通文字上的纠错、无纠错句子、切换/清空/大字/窄屏后的残留与溢出，以及从句清单、短从句嵌套外框、长从句跨行范围条带、两层和三层嵌套、短从句只列清单、重分析/换例句/清空后的残留清理，以及静态 Pages 下的密钥设置、存储失败、一次格式修正及取消。设置 `BROWSER_CHANNEL=msedge` 可改用本机 Edge，或用 `BROWSER_EXECUTABLE` 指定浏览器可执行文件。

后续顺序见[待办与路线图](roadmap.md)，人工检查用的句子见[语法回归样例](regression-cases.md)。模拟响应测试不代表真实模型已经通过这些语法样例。
